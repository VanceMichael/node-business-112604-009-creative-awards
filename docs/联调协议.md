# 奖励合作方接收端

联调端只接收请求、保存流水和返回人工安排的外部结果，不判断业务资格、库存、配比、名次或可付款金额。`data/peer.json` 列出操作名称及领域字段。

所有请求使用 JSON，健康检查为 `GET /health`。其余请求带 `x-peer-key: local-synthetic-peer`；这个公开值只隔开联调控制面，不是生产鉴权凭据。生产服务的身份与权限需要独立处理。

向 `POST /operations/操作名称` 发送含 `requestId` 的业务对象。流水号为 1—100 位字母、数字、下划线、点或连字符，标识同一次外部意图。相同流水和相同 JSON 内容可重发，字段顺序不影响；同流水不同内容返回 409。未知操作返回 404。本接收端整体共享流水空间。

响应保存 `requestId`、`operation`、原始 `body`、`acceptedAt` 与 `result`，其中 `acceptedAt` 是联调端接收时间；领域实际发生时间位于 `result`。`GET /requests/流水号` 返回已保存流水，不存在返回 404。受理后断连仍会保存，重启仍可查到，不必重造请求。默认结果仅为 accepted，不暗示任何后续履行。

人工可在发送前用 `PUT /admin/plans/流水号` 配置 `mode` 与 `result`，模式为 normal 或 disconnectAfterAccept。后一模式首次受理后断连，不发送 HTTP 响应；相同请求重发会直接返回既有流水。`PUT /admin/results/流水号` 将已有流水的结果替换为随后核实的外部事实；不存在的流水返回 404。`GET /admin/requests` 供本地人员核对实际收到的请求。这些控制接口属于协作方联调，不是业务用户接口。

issue 返回 grantId、accountId、issuedAt；revoke 引用 grantId，返回 revoked 或 irrevocable。HTTP 受理与实际发放独立，查询可以出现 pending。

`identity_fields` 列出各操作使用的领域标识提示，只有 `requestId` 由联调端统一校验，其余字段及结果的适用范围由实际协作协议和业务服务校核。联调端不会自动制造后续回执；可在原流水上配置后续事实，再由业务服务查询或通过其回执入口接收。错误 JSON 返回 400，未带联调标识返回 401。
